# Open Questions

> Per `CLAUDE.md` §7: when the spec is ambiguous, or a real public source cannot be verified, the
> question is written here rather than guessed at. Pascal escalates to the architect.
>
> **How to use this file.** One row per question. Do not delete rows — move them to
> [§3 Resolved](#3-resolved) with the answer recorded, so the reasoning survives. `Blocking?` means
> *blocking for the week named*, not blocking forever. Where an implementation had to proceed without
> an answer, the assumption made is stated in §2 so it can be reversed cheaply if the answer differs.

| Q-02 (partial) | Permission **identifier scheme** — `verb:object` or `object.verb`? | **`verb:object`, singular object.** Both forms shipped in parallel in the Week 1 scaffold (`read:consular_case` in `docs/workflows.md`, `consular.read` in `apps/web/src/lib/nav.ts`) with zero string overlap, which would have rendered the permission-derived nav rail permanently empty. `verb:object` wins because it already carries the 21 workflow permissions and their full 6-role grant matrices, and because it expresses transition permissions (`approve:meeting_followup`, `resolve:consular_case`) that `object.verb` cannot without a second parallel scheme. `nav.ts` was rewritten to match. **The full role→permission matrix remains open in §1.** | Lead Engineer | 2026-09-07 |
| Q-03 (partial) | Permitted values of `approval_status`. | **The proposed 5-value set is adopted: `NOT_REQUIRED`, `PENDING_APPROVAL`, `APPROVED`, `REJECTED`, `BLOCKED`.** `BLOCKED` is load-bearing, not decorative: it is the state a Gateway refusal or an uncovered fallback produces, and it is the state most likely to appear on stage. The envelope's `result` is therefore nullable, and `packages/contracts/src/index.ts` types it as `TResult \| null` so that forgetting to narrow on `approval_status` is a compile error rather than a blank panel in front of the Ambassador. **Ownership of the field (AI artefact only, or also persisted on `actions`) remains open in §1.** | Lead Engineer | 2026-09-07 |
